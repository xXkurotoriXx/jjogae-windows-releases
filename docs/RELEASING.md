# Windows 개발·릴리스

소스·문서·CI·릴리스·업데이트는 `xXkurotoriXx/jjogae-windows-releases` 하나에서 관리합니다. 0.4.15부터 사용하는 공개 업데이트 주소는 유지됩니다. 옛 비공개 소스 저장소가 빌드나 다운로드에 필요하지 않습니다.

1. 소스를 수정하고 `Directory.Build.props` 버전을 올립니다. 개인정보처리방침·제3자 고지·설치 안내를 실제 동작에 맞춥니다. 릴리스 설명은 `RELEASE_NOTES.md`에 기록합니다.
2. main의 Windows build가 두 검증 작업 모두 통과했는지 확인합니다. 토큰·쿠키·사용자 기록·빌드 결과·개인 이메일을 커밋하지 않습니다.
3. 검증할 정확한 소스 커밋에 해당 버전 태그를 붙여 push합니다. Windows release는 같은 커밋을 두 Windows 작업으로 다시 검증한 뒤 검증 자산을 게시합니다.
4. 게시된 EXE·체크섬·문서·update.json을 익명으로 다운로드해 SHA-256, 크기와 파일 버전을 대조합니다. 설치 앱의 확인·업데이트·정상 시작·설정 보존을 검증합니다.

게시 작업에만 저장소 범위의 Actions GITHUB_TOKEN을 사용합니다. 별도 개인 토큰·Git Credential Manager·저장소 간 자격증명이 필요하지 않습니다. 앱 업데이트는 GitHub 인증을 사용하지 않습니다. 기존 버전 자산을 덮어쓰지 않습니다. ZIP은 공개 릴리스에 올리지 않습니다.

업데이트 설치 도우미는 기존 파일을 보관하고 새 실행 파일의 정상 시작 신호가 없으면 복구합니다. 0.4.16부터 정상 시작 확인 후 마지막 성공 확인 시간을 저장합니다. Windows EXE는 현재 Authenticode 서명이 없으며 HTTPS·SHA-256·체크섬·크기·파일 버전을 검증합니다.
